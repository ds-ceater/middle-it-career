# ARTICLE_RULES.md
# Astro転職アフィリエイトサイト：記事制作・SEO運用ルール

このファイルは、当サイトの記事を新規作成・編集・更新する際の共通ルールです。

記事を作成する前に必ず本ファイルを確認し、すべてのルールに従ってください。

---

# 1. サイト運営の基本方針

## 1-1. サイトの目的

IT業界を中心とした転職情報を提供し、読者の転職活動を支援する。

最終的には、読者に適切な転職サービスを紹介し、アフィリエイト収益につなげる。

ただし、収益を優先して読者に不利益な情報を隠してはならない。

## 1-2. 記事制作の基本原則

以下を必ず守る。

1. 検索ユーザーの疑問や悩みに正確に回答する。
2. 検索意図を満たす記事を作成する。
3. 読者にとって有益な情報を優先する。
4. 正確性と信頼性を重視する。
5. 読みやすく、理解しやすい文章にする。
6. 不必要な文章の水増しをしない。
7. 他サイトの文章をコピーしない。
8. 他の記事と内容が重複しないようにする。
9. 定期的に情報を確認・更新できる構造にする。
10. 読者の判断に役立つ情報を提供する。

検索順位だけを目的とした記事ではなく、読者の問題解決を目的とした記事を作成する。

# 2. ファイル名・URLの命名規則

## 2-1. 基本ルール

記事ファイル名は英語の小文字で統一する。

以下のルールを守る。

- 英語の小文字を使用する。
- 単語はハイフン（-）で区切る。
- 日本語は使用しない。
- アンダースコア（_）は使用しない。
- 不必要に長いファイル名にしない。
- 記事の主題が分かる名前にする。
- メインキーワードに関連する単語を含める。
- 同じファイル名を使用しない。
- 公開済み記事のファイル名は原則変更しない。
- 年号や日付は原則含めない。

## 2-2. ファイル名の形式

基本形式：

`[対象・属性]-[ジャンル・キーワード]-[記事内容].mdx`

ただし、すべてのファイル名を無理に同じ形式にする必要はない。

自然で短く、記事の内容が伝わることを優先する。

## 2-3. ファイル名の例

| 記事内容 | ファイル名 |
|---|---|
| 50代のIT転職 | 50s-it-career-change.mdx |
| 30代のIT転職 | 30s-it-career-change.mdx |
| IT転職の未経験者向けガイド | it-career-change-no-experience.mdx |
| IT転職エージェント比較 | it-recruitment-agents-comparison.mdx |
| 転職エージェントの評判 | agent-name-reviews.mdx |
| ITエンジニアの年収 | it-engineer-salary-guide.mdx |
| IT転職の面接対策 | it-job-interview-guide.mdx |

## 2-4. URL変更の禁止事項

公開済み記事のURLを安易に変更しない。

SEO評価や外部リンクを失う可能性があるため、変更が必要な場合は301リダイレクトを設定する。

新規記事作成時は、既存記事とのURL重複がないか確認する。

# 3. Frontmatterの統一ルール

すべての記事でFrontmatterの形式を統一する。

基本テンプレート：

```yaml
---
title: "記事タイトル"
description: "記事の内容を簡潔に説明する文章"
pubDate: 2026-11-07
updatedDate: 2026-11-07
category: "カテゴリー"
tags:
  - タグ1
  - タグ2
  - タグ3
---
```

※実際のフィールド名・必須項目・データ型は、Astroプロジェクト内のcontent.config.tsまたは既存のスキーマを優先する。

既存スキーマに存在しないフィールドを勝手に追加しない。

## 3-1. title

- 記事のメインキーワードを自然に含める。
- 記事内容を正確に表現する。
- 読者が記事を読むメリットを伝える。
- 不自然なキーワードの詰め込みをしない。
- 内容と異なる誇張表現を使わない。
- 同一サイト内で似たタイトルを乱発しない。

目安は30〜36文字程度。ただし文字数よりも分かりやすさを優先する。

## 3-2. description

- 記事内容を具体的に説明する。
- メインキーワードを自然に含める。
- 読者が得られる情報を伝える。
- 記事内容と一致させる。
- 記事ごとに固有の文章にする。

目安は100〜130文字程度。

検索結果での表示を意識し、前半に重要な内容を配置する。

## 3-3. pubDate

初回公開日を設定する。

形式はプロジェクトのスキーマに合わせる。

## 3-4. updatedDate

記事を実質的に更新した場合に更新日を変更する。

誤字修正や軽微な表現変更だけで更新日を変更しない。

更新していない記事に新しい更新日を設定しない。

## 3-5. category

カテゴリーは既存の分類体系から選択する。

新しいカテゴリーを作る前に既存カテゴリーを確認する。

似たカテゴリーを乱立させない。

## 3-6. tags

- 記事に関連するタグを設定する。
- 不必要に多く設定しない。
- 表記揺れを防ぐ。
- 既存タグを優先して使用する。
- 同じ意味のタグを複数作らない。

# 4. SEOキーワードの選定ルール

## 4-1. メインキーワード

記事ごとにメインキーワードを1つ設定する。

メインキーワードは、その記事が解決する検索ニーズを最もよく表すものとする。

例：

記事テーマ：50代のIT転職

メインキーワード：
「50代 IT転職」

## 4-2. 関連キーワード

メインキーワードに関連する検索語を選定する。

例：

- 50代 IT転職 難しい
- 50代 ITエンジニア 求人
- 50代 IT転職 年収
- 50代 IT転職 未経験
- 50代 転職エージェント
- 50代 IT転職 成功

関連キーワードを不自然に詰め込まない。

記事内で必要な情報として自然に扱う。

## 4-3. 検索意図の分析

執筆前に以下を確認する。

1. 読者は何を知りたいのか。
2. なぜそのキーワードで検索したのか。
3. 読者が抱えている不安や問題は何か。
4. 記事を読んだ後に何を判断できる必要があるか。
5. 読者が次に取るべき行動は何か。

検索意図に直接回答する内容を記事の前半に配置する。

## 4-4. キーワードの過剰使用を禁止

以下は禁止する。

- 同じキーワードを不自然に繰り返す。
- すべての見出しに同じキーワードを入れる。
- 文脈に関係のない関連キーワードを追加する。
- 読みやすさを犠牲にしてキーワードを詰め込む。

自然な日本語を優先する。

# 5. 記事構成のルール

## 5-1. 基本構成

原則として以下の構成を採用する。

1. 導入文
2. 読者の疑問に対する結論
3. 詳細な解説
4. 比較・具体例・判断材料
5. 注意点・デメリット
6. よくある質問
7. まとめ
8. 関連記事への内部リンク
9. 必要に応じたCTA

記事のテーマに応じて順番や項目を変更してよい。

すべての記事に同じ構成を機械的に適用しない。

## 5-2. 導入文

導入文では以下を意識する。

- 読者の悩みを明確にする。
- 記事で扱う内容を説明する。
- 重要な結論を簡潔に伝える。
- 読み進めるメリットを示す。

導入文は長くしすぎない。

一般的な挨拶や不必要な前置きは禁止する。

## 5-3. 見出し構造

見出しは以下の階層を使用する。

```markdown
# 記事タイトル

## 大見出し

### 小見出し
```

ルール：

- H1は原則1記事につき1つ。
- H2は記事の主要テーマを表す。
- H3はH2の内容を具体的に説明する。
- H4は必要な場合のみ使用する。
- 見出しの階層を飛ばさない。
- 見出しだけで記事内容の全体像が分かるようにする。
- 見出しに無理やりキーワードを入れない。

## 5-4. 見出しの作成

見出しは具体的で分かりやすくする。

悪い例：

「転職について」

良い例：

「50代のIT転職が難しいといわれる理由」

悪い例：

「おすすめについて」

良い例：

「50代のITエンジニアにおすすめの転職エージェント」

# 6. 文章作成のルール

## 6-1. 基本的な文体

- 自然な日本語を使用する。
- 原則として「です・ます」調に統一する。
- 専門用語は必要に応じて説明する。
- 一文を長くしすぎない。
- 同じ表現を繰り返さない。
- 結論を先に伝える。
- 抽象的な説明だけで終わらせない。

## 6-2. 文章の長さ

スマートフォンで読みやすい文章を意識する。

- 1段落は原則2〜4文程度。
- 1文は適度な長さにする。
- 長い説明は見出しやリストで分割する。
- 重要な情報は表に整理する。
- 箇条書きは比較や手順の説明に活用する。

文字数を増やすこと自体を目的にしない。

## 6-3. 禁止する文章表現

以下のような表現を多用しない。

- 「いかがでしたでしょうか」
- 「いかがでしたか」の繰り返し
- 「非常に重要です」の連発
- 「ぜひ参考にしてください」の連発
- 「〜といえるでしょう」の連発
- 「まずは確認してみましょう」の連発

同じ言い回しが複数の記事で繰り返されないようにする。

# 7. 記事の文字数

文字数は検索意図と情報量に応じて決定する。

目安：

| 記事タイプ | 文字数の目安 |
|---|---:|
| 基礎知識・用語解説 | 2,000〜3,500文字 |
| 転職ノウハウ | 3,000〜5,000文字 |
| 年代別転職 | 3,000〜5,000文字 |
| サービス紹介 | 2,500〜4,500文字 |
| サービス比較 | 4,000〜7,000文字 |
| 総合ガイド | 5,000〜8,000文字 |

上記は制作上の目安であり、SEO上の必須文字数ではない。

検索意図を十分に満たせる場合は、無理に文字数を増やさない。

# 8. 情報の正確性・信頼性

転職ジャンルは、読者の仕事や収入、生活に影響するテーマである。

情報の正確性を特に重視する。

## 8-1. 情報源

情報を調べる場合は、以下の情報源を優先する。

1. 官公庁・公的機関
2. 企業・サービスの公式サイト
3. 公式の調査資料・統計資料
4. 信頼性の高い調査機関
5. 専門性の高い報道機関
6. その他の参考情報

## 8-2. 数値・統計データ

数値や統計を記載する場合は以下を確認する。

- 調査主体
- 調査対象
- 調査時期
- 調査方法
- データの対象範囲
- 公開元のURL

古い統計を現在の状況として紹介しない。

特定企業の調査結果を業界全体の実態として扱わない。

## 8-3. 禁止事項

以下を絶対に行わない。

- 架空の統計データを作る。
- 存在しない調査結果を紹介する。
- 架空の口コミを掲載する。
- 架空の利用者体験談を作る。
- 実在しない求人情報を紹介する。
- 未確認の年収データを断定する。
- 公式情報にないサービス内容を記載する。
- 確認していない内容を事実として断定する。

情報を確認できない場合は、無理に補完しない。

必要に応じて「公式情報では確認できませんでした」などと明記する。

## 8-4. 引用・参考情報

外部の情報を利用する場合は、出典を明記する。

参考情報には可能な限り以下を含める。

- 情報元の名称
- 資料やページの名称
- URL
- 公開日または更新日（確認できる場合）

他サイトの文章をそのまま転載しない。

統計や調査結果は、元資料の意味を変えないように説明する。

# 9. 転職ジャンル・YMYL対策

転職情報は、読者の収入や生活設計に影響するため、特に信頼性を重視する。

以下を守る。

- 事実と個人の意見を区別する。
- 断定的な転職成功の保証をしない。
- 不確かな年収情報を断定しない。
- 特定のサービスを根拠なく最上位にしない。
- デメリットや注意点も説明する。
- 求人条件やサービス内容の最新情報を確認する。
- 公的な制度や法律については公式情報を確認する。
- 必要に応じて専門家による確認を検討する。

「絶対に転職できる」「必ず年収が上がる」などの表現は禁止する。

経験や属性によって結果が異なることを適切に説明する。

# 10. アフィリエイト記事の作成ルール

## 10-1. 基本方針

アフィリエイトリンクは、読者の判断を助ける目的で設置する。

無理に申込みを促すのではなく、読者がサービスを利用するメリットを理解できるようにする。

## 10-2. CTAの配置

CTAは以下の位置を検討する。

- サービス紹介直後
- 比較表の直後
- 読者の悩みを解決する方法を説明した後
- 記事のまとめ付近

ただし、すべての場所にCTAを設置する必要はない。

記事の内容と読者の検討段階に応じて判断する。

## 10-3. サービス紹介

転職サービスを紹介する際は以下を説明する。

- サービスの特徴
- 対象となる利用者
- 得意とする業界・職種
- 利用するメリット
- 注意点・デメリット
- 利用条件
- 公式サイト

確認できないサービス内容を推測で記載しない。

## 10-4. 比較記事

比較記事では、統一された比較基準を使用する。

例：

| 比較項目 | 内容 |
|---|---|
| 対象年齢 | 公式情報で確認 |
| 得意分野 | 公式情報で確認 |
| 求人数 | 調査日時点の情報 |
| 対応地域 | 公式情報で確認 |
| 利用料金 | 利用者負担の有無 |
| サポート内容 | 公式情報で確認 |

比較基準を明示し、根拠なく順位を決定しない。

広告案件の報酬額だけでランキングを決めない。

## 10-5. 広告表示

広告・アフィリエイトを含む記事では、読者が広告であることを認識できるようにする。

サイトの共通広告表示ルールに従い、必要な表示を行う。

広告であることを隠した表現は禁止する。

# 11. 内部リンクのルール

内部リンクは、読者が次に知りたい情報へ移動できるように設置する。

## 11-1. リンク先の選定

以下を優先する。

- 同じテーマの関連記事
- より詳しい解説記事
- サービス比較記事
- 転職ノウハウ記事
- 読者の次の行動に役立つ記事

## 11-2. アンカーテキスト

リンク先の内容が分かる具体的な文章にする。

良い例：

「50代のIT転職に対応している転職エージェントを比較する」

悪い例：

「こちら」
「詳しくはこちら」

## 11-3. 内部リンクの禁止事項

- 存在しない記事へのリンクを作らない。
- URLを推測して作らない。
- 関係のない記事へ無理にリンクしない。
- 同じリンクを不必要に繰り返さない。

新規記事作成時は、既存記事一覧を確認して適切な内部リンクを追加する。

適切な記事が存在しない場合は、リンクを無理に追加しない。

# 12. 関連記事・トピッククラスター

サイト全体でテーマごとの専門性を高めるため、関連記事をグループ化する。

例：

## IT転職

- IT転職の基礎知識
- IT転職エージェント比較
- ITエンジニアの年収
- IT転職の面接対策
- IT転職の職務経歴書

## 年代別転職

- 20代のIT転職
- 30代のIT転職
- 40代のIT転職
- 50代のIT転職

## 職種別転職

- システムエンジニアの転職
- インフラエンジニアの転職
- プロジェクトマネージャーの転職
- ITコンサルタントの転職

同じ検索意図を持つ記事を複数作らない。

既存記事と検索意図が重複する場合は、新規記事を作る前に既存記事の改善を検討する。

# 13. Markdown・MDXの記述ルール

## 13-1. 基本形式

記事は原則としてMarkdown形式（.mdx）で作成する。

Frontmatterの後に本文を記述する。

## 13-2. 使用する記法

- 見出し：Markdown見出し
- 箇条書き：Markdownリスト
- 表：Markdownテーブル
- 強調：必要な箇所のみ太字
- リンク：Markdownリンク
- 引用：必要な場合のみ引用記法

## 13-3. MDXの注意点

- 既存プロジェクトで定義されていないコンポーネントを使用しない。
- JSXとして解釈される記号やタグに注意する。
- 属性やコンポーネントの構文を正しく記述する。
- HTMLを使用する場合はAstroの既存実装との互換性を確認する。
- 不必要に複雑なMDXにしない。

## 13-4. 表の作成

比較表や一覧表は積極的に活用する。

ただし、スマートフォンで読みづらくなるような巨大な表は避ける。

比較項目を絞り、重要な情報を優先する。

## 13-5. 画像

画像を使用する場合は以下を守る。

- 記事内容と関連する画像を使用する。
- alt属性を適切に設定する。
- 画像の著作権・利用条件を確認する。
- 装飾目的だけの画像を大量に追加しない。
- 画像がなくても内容を理解できる記事にする。

# 14. 既存記事の更新ルール

記事を更新する場合は、既存の内容を確認してから編集する。

## 14-1. 更新前の確認

以下を確認する。

- 現在の記事内容
- 現在の検索意図との適合性
- 情報の正確性
- 古い統計やデータの有無
- リンク切れ
- 内部リンク
- タイトルとdescription
- 競合記事との差別化

## 14-2. 更新時の基本方針

- 正確な情報に修正する。
- 古い情報を新しい情報に更新する。
- 不要な説明を削除する。
- 不足している情報を追加する。
- 検索意図から外れた内容を整理する。
- 読みやすさを改善する。
- 内部リンクを見直す。

単に文章量を増やすだけの更新は禁止する。

## 14-3. 更新日

実質的な更新を行った場合のみupdatedDateを変更する。

初回公開日は変更しない。

## 14-4. URL

記事更新時は原則としてslugを変更しない。

タイトルを変更しても、URLを変更する必要があるとは限らない。

# 15. 新規記事作成前の確認事項

新しい記事を書く前に、以下を確認する。

1. 同じキーワードを狙った記事が存在しないか。
2. 既存記事と検索意図が重複していないか。
3. 既存記事のリライトで対応できないか。
4. 適切なカテゴリーが存在するか。
5. 内部リンク先となる記事が存在するか。
6. 信頼できる情報源を確保できるか。
7. 記事を作るだけの独自性や情報価値があるか。

確認できない情報は推測で補わない。

# 17. Claude Codeの作業ルール

# 18. SEO運用上の重要事項

以下の点を理解して記事を制作する。

- 記事の文字数が多いだけでは検索順位は上がらない。
- キーワードを多く入れるだけでは検索順位は上がらない。
- 同じテーマの記事を大量に作ることが必ずしも有利とは限らない。
- AIで生成した記事でも、内容の正確性と有用性が重要である。
- 独自の経験、検証、一次情報は積極的に追加する。
- 検索順位だけでなく、読者の満足度を重視する。
- アフィリエイトリンクの数を増やすこと自体を目的にしない。
- 公開後も検索状況や情報の鮮度を確認する。

# 最終原則

当サイトの記事制作では、次の優先順位を守る。

1. 情報の正確性
2. 読者の検索意図への適合
3. 読みやすさと分かりやすさ
4. 独自性・専門性・信頼性
5. SEOの最適化
6. アフィリエイト収益への導線

検索エンジン向けに不自然な文章を作らない。

読者にとって本当に役立つ記事を作成し、その結果として検索流入とアフィリエイト収益を獲得することを目指す。

このルールは、当サイトのすべての新規記事作成・リライト・更新作業に適用する。
